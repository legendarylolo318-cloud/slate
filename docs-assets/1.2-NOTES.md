| 13 | Crossfade | Done, off by default (Settings → Playback, 0–12 s as steps of 2). **Design differs from the brief:** not a second decode branch inside one pipeline. A second audio *worker* starts the next track silent, the two are ramped with equal-power curves, the new worker becomes the player at once and the old one is shut down when the ramp ends (the only thread it owns is the ramp). That keeps each track's own ReplayGain and the existing gapless graph untouched when off. Tested with the real worker on two generated tones (`tests/crossfade_engine.rs`, run with `--ignored`; makes a quiet sound): swap, MODIFIED, clean end, skip mid-fade. **Not verified by ear** on real tracks: click-free transitions, and pause/seek mid-fade beyond the code paths. Slider is a 7-step selector, not 1–12 s per second. |

## Decisions
* MCP is now a stateful Streamable-HTTP session (same URL and loopback / Host protections) so that
  the client name and subscriptions work.
* Dormancy: the MCP, party and DJ hooks begin with one atomic check; a source-guard test enforces it
  for the MCP hooks. Party state lives in statics created at start and cleared at end.
* The MCP play log for `get_listening_stats` is only written while the server runs.
* The existing MCP `create_playlist` still makes PUBLIC playlists; new tools create UNLISTED ones.
